# M5 官方库参考笔记（StopWatch 硬件）

> 用途：以后要碰屏幕/触摸/按键/振动/麦克风/电源时，先看这份，别重新摸索。
> 写于 2026-10-13。**验证状态逐个标注** —— 标"未验证"的是我没能拿到原文、只按你的描述整理的。

## 0. 最重要的一句话

**你给的这三个库都是 Arduino 生态优先的**（M5Unified / M5GFX），而**本工程是 ESP-IDF 5.5 + LVGL 9.5**，
不能直接 `#include`。它们的价值是**三方面**：

1. **M5PM1** —— 有 ESP-IDF 原生入口，而且**本工程已经把它作为 managed component 在用**（见 §2）。
2. **M5IOE1**（你没提但同族）—— 同样已在用（见 §3）。
3. **M5Unified / M5GFX** —— 当**参考资料**用：板级引脚表、外设初始化顺序、CO5300 初始化序列、
   圆形屏裁剪/偏移参数。（见 §4）

## 2. M5PM1（电源管理，I2C 0x6E）

**本工程已经在用** —— `main/boards/m5stack-stopwatch/m5stack_stopwatch.cc`：

```cpp
pmic_.begin(i2c_bus_, M5PM1_DEFAULT_ADDR, M5PM1_I2C_FREQ_100K);  // ESP-IDF：传 i2c_master_bus_handle_t
pmic_.setChargeEnable(true);        // 允许充电
pmic_.setBoostEnable(true);         // 开 boost
pmic_.pinMode(PMIC_PIN_CHARGE_STATE, INPUT);
pmic_.pinMode(PMIC_PIN_CHARGE_PROG, OUTPUT);
pmic_.digitalWrite(PMIC_PIN_CHARGE_PROG, LOW);   // 充电电流 425mA（拉高是另一档）
uint16_t mv = 0; pmic_.readVbat(&mv);            // 电量百分比就是拿这个折算的
bool charging = (pmic_.digitalRead(PMIC_PIN_CHARGE_STATE) == 0);  // 注意：低电平 = 正在充电
```

### 接口全貌（按用途查，比翻 138KB 的 M5PM1.h 快）

| 用途 | 接口 |
|---|---|
| 设备信息 | `getDeviceId` / `getDeviceModel` / `getHwVersion` / `getSwVersion` |
| 电压 | `readVbat` / `readVin` / `read5VInOut` / `readVref` / `getRefVoltage` |
| 电源开关 | `setChargeEnable` / `setDcdcEnable` / `setLdoEnable` / `setBoostEnable` |
| 电源保持 | `gpioSetPowerHold` / `ldoSetPowerHold` / `boostSetPowerHold` |
| ADC/温度 | `analogRead` / `readTemperature` / `disableAdc` / `isAdcBusy` |
| PWM | `setPwmFrequency` / `setPwmDuty`(0-100%) / `setPwmDuty12bit`(0-4095) / `analogWrite`(0-255) |
| GPIO | `pinMode` / `digitalWrite` / `digitalRead`（另有 `xxxWithRes` 带返回码版本） |
| 按钮 | `btnSetConfig` / `btnGetState` / `btnGetFlag` |
| 中断 | `irqGetGpioStatus` / `irqGetSysStatus` / `irqGetBtnStatus`（另有 `...Enum` 枚举版）+ `irqSetXxxMask` 屏蔽 |
| 系统 | `sysCmd` / `shutdown` / `reboot` / `enterDownloadMode` |
| 低功耗 | `setI2cSleepTime` / `setAutoWakeEnable` / `sendWakeSignal` / `timerSet` / `wdtSet` |
| RTC RAM | `writeRtcRAM` / `readRtcRAM` ← **重启后要保住的状态可以放这** |
| NeoPixel | `setLeds` / `setLedColor` / `refreshLeds` / `disableLeds`（**仅 GPIO0**，1-32 颗） |
| 音频功放 | `setAw8737aPulse` / `setAw8737aMode`（AW8737A 增益模式 MODE_1~4）← **换喇叭增益看这里** |
| 电池保护 | `setBatteryLvp` |

**高危**（用错要断电才能恢复）：`setDownloadLock`、`setSingleResetDisable`、`setDoubleOffDisable`。

**引脚能力限制**（做低功耗/唤醒前必看）：
- WAKE：GPIO0/2/3/4 支持，**GPIO1 不支持**；且 0↔2、3↔4 互斥
- ADC：GPIO1=ADC1、GPIO2=ADC2；PWM：GPIO3=PWM0、GPIO4=PWM1（**频率全通道共享**）
- NeoPixel：**只有 GPIO0**，刷新时 I2C 短暂不可中断
- I2C 休眠：PWM 使能或下载模式下失效

**本工程没用上、但以后可能会用**：`readTemperature`、`getPowerSource`（USB/电池判定）、
`irqGetSysStatus`（USB 插拔中断）、`shutdown` 深度关机、`setBatteryLvp`、RTC RAM。

## 3. M5IOE1（I2C IO 扩展，0x4F）

**本工程已经在用** —— 引脚定义在 `main/boards/m5stack-stopwatch/config.h`：

| 宏 | IOE 引脚 | 作用 |
|---|---|---|
| `IOE_PIN_LCD_POWER` | PIN_8 | 屏电源 |
| `IOE_PIN_LCD_RST` | PIN_5 | 屏复位 |
| `IOE_PIN_TOUCH_RST` | PIN_4 | 触摸复位 |
| `IOE_PIN_CODEC_POWER` | PIN_3 | 音频 codec 电源 |
| `IOE_PIN_PA_EN` | PIN_10 | 功放使能 |
| `IOE_PIN_MOTOR` | PIN_9 | **振动马达**（`pinMode(OUTPUT)` + `digitalWrite(HIGH/LOW)` 直接控制，没有 `vibrate()` 这种封装） |

```cpp
ioe_.begin(i2c_bus_, M5IOE1_I2C_ADDR, M5IOE1_I2C_FREQ_100K, M5IOE1_INT_MODE_POLLING);
ioe_.pinMode(IOE_PIN_MOTOR, OUTPUT);
ioe_.setDriveMode(IOE_PIN_MOTOR, M5IOE1_DRIVE_PUSHPULL);   // 开漏要给外部上拉
ioe_.digitalWrite(IOE_PIN_MOTOR, LOW);
```

**⚠️ include 顺序坑（官方 README 明确写了）**：ESP-IDF ≥5.3 且没开
`CONFIG_I2C_BUS_BACKWARD_CONFIG` 时，`i2c_bus.h` 会自己定义一份 `i2c_config_t` ——
如果**和 M5Unified 同时用**，必须先 `#include <M5Unified.h>` 再 `#include <M5IOE1.h>`，
反了就是 `i2c_config_t` 重复定义。M5PM1 同样有这个约束（其 README 也提了）。
本项目目前只用了这两个独立组件、没引 M5Unified，所以没这个问题。

## 4. M5Unified / M5GFX（**未验证**，仅供参考方向）

> 下面这段是按你给的一句话描述 + 通识整理的，**我没能读到原文**（github.com 与
> raw.githubusercontent.com 都被本机网络策略挡住了）。要用之前请自己开链接核一遍。

- **M5Unified**：统一抽象层，一套 API 覆盖各机型的外设（显示/触摸/按键/麦克风/喇叭/IMU/电源/振动），
  用 `M5.begin()` 一把初始化，靠 `M5.config()` 选机型。**Arduino 优先**，但近年也提供了 ESP-IDF 入口
  （M5PM1/M5IOE1 的 `begin(m5::I2C_Class*, ...)` 重载就是为它准备的）。
- **M5GFX**：LovyanGFX 血统的图形库，管面板驱动、DMA、旋转、圆形屏裁剪、AMOLED 亮度。

**在本工程里怎么当参考**（不建议引入）：

| 想解决的问题 | 去看 M5GFX/M5Unified 的什么 | 本工程现在的做法 |
|---|---|---|
| CO5300 初始化/时序对不对 | 其 CO5300 面板定义与 init 序列 | `main/boards/m5stack-stopwatch/m5stack_stopwatch.cc:34-46` 的 `vendor_specific_init[]` + `espressif__esp_lcd_co5300` |
| 圆形屏裁剪/圆角遮罩 | M5GFX 的圆屏裁剪实现 | 本工程靠布局避让：`DISPLAY_ROUND_EDGE_INSET=56`（config.h），关键内容收在居中 329×329 |
| AMOLED 亮度/省电 | M5GFX 的 AMOLED 亮度控制 | 直接发 `0x51` 命令（`StopwatchBacklight::SetBrightnessImpl`）；纯黑不发光 |
| 各机型引脚表 | M5Unified 的 board 表 | 本机 `config.h` 已是权威 |
| 外设上电顺序 | `M5.begin()` 内部顺序 | `InitializeI2c() → Spi → Display → Touch → Buttons`（顺序有依赖，别乱调） |

**如果以后真要引 M5Unified**：它是 Arduino 库，本工程是纯 ESP-IDF (CMake)，得走
"Arduino as an ESP-IDF component" 那条路，且会和现有的 `espressif__button`、
`esp_codec_dev`、`espressif__esp_lcd_co5300`、自写的 `cst820` 重复 —— **收益很低，不建议**。

## 5. 本工程硬件栈对照（谁在管什么）

| 子系统 | 本工程用的 | 备注 |
|---|---|---|
| 屏幕驱动 | `espressif__esp_lcd_co5300` + `espressif__esp_lvgl_port` | QSPI，466×466，RGB565 |
